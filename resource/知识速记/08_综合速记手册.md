## PART A：数字必背（法律法规 + 技术规定）

### 著作权法
| 保护期限 | 内容 |
|----------|------|
| 公民作品 | 作者终生+**50年** |
| 法人/单位作品 | 首次发表后**50年** |
| 电影/软件 | 首次发表后**50年** |
| 人身权（署名权等） | **永久保护** |

### 专利法
| 类型 | 保护期 | 自申请日起 |
|------|--------|-----------|
| 发明专利 | **20年** | ✓ |
| 实用新型 | **10年** | ✓ |
| 外观设计 | **15年** | ✓（2021年修订从10年改为15年）|

### 网络安全法关键数字
- 网络日志保留：**不少于6个月**
- 个人信息泄露通知：**发现后立即通知**，重大泄露需报网信部门

### 招标投标法
| 内容 | 数字 |
|------|------|
| 招标文件出售截止时间 | 投标截止前**不少于5天** |
| 提交投标文件截止后修改 | **不允许** |
| 评标有效期内更换评委 | 不得随意更换 |
| 中标通知书发出后签合同 | **30日内** |
| 项目金额强制招标（货物） | **≥200万元** |
| 项目金额强制招标（服务） | **≥100万元** |
| 项目金额强制招标（施工） | **≥400万元**（单项合同）|

### 政府采购法
- 政府采购限额标准由**财政部**制定
- 货物和服务：**≥100万元**需公开招标
- 工程：按招标投标法

## PART D：高频"概念辨析"（常出选择题）

### 1. 三种基准的区别
- **范围基准** = 批准的范围说明书 + WBS + WBS词典
- **进度基准** = 批准的进度模型
- **成本基准** = 批准的项目预算（不含管理储备）
- **绩效测量基准（PMB）** = 范围基准 + 进度基准 + 成本基准

### 2. 两种储备的区别
- **应急储备**：已知风险（已识别）→ 包含在成本基准内，PM有权使用
- **管理储备**：未知风险（未识别）→ 不在成本基准内，需高层批准

### 3. 问题 vs 风险
- **问题**：已经发生的不利事件（issue）
- **风险**：未来可能发生的不确定事件（risk）

### 4. 需求 vs 范围
- **产品范围**：项目最终交付物的特性和功能（满足需求）
- **项目范围**：为交付产品所需完成的全部工作

### 5. 项目经理的权力来源
- **正式权力**：来自组织授权（组织章程）
- **专家权力**：来自专业知识
- **奖励权力**：能够给予奖励
- **惩罚权力**：能够施加惩罚
- **参照权力**：个人魅力，被别人视为榜样

## PART E：配置管理与变更管理辨析

### 变更控制委员会（CCB）
- 负责审查、批准或拒绝变更请求
- 通常由**项目发起人、项目经理、主要干系人**组成
- **项目经理不能单独审批影响基准的变更**

### 配置管理系统
- 变更控制系统是配置管理系统的子集
- 配置项的变更必须通过变更控制系统

### 版本控制
- 追踪可交付成果的不同版本
- 确保团队成员使用最新版本

## PART F：进度压缩与估算方法汇总

### 进度压缩
| 方法 | 特点 | 成本 | 风险 |
|------|------|------|------|
| 赶工 | 增加资源（加人/加班）| 增加 | 低（可控）|
| 快速跟进 | 活动并行执行 | 不一定增加 | 高（可能返工）|

### 活动历时估算方法
| 方法 | 特点 | 准确度 |
|------|------|--------|
| 专家判断 | 依靠专家经验 | 中 |
| 类比估算 | 参考历史相似项目 | 低（但快）|
| 参数估算 | 用统计关系（单位时间/成本）| 中-高 |
| 三点估算（PERT） | 乐观+最可能×4+悲观)/6 | 高 |
| 自下而上估算 | 汇总WBS工作包 | 最高（但慢）|

## PART G：2026年高频新考点（近年趋势）

### CPSD模型（信息物理社会决策模型）
- C = Cyber（网络/信息空间）
- P = Physical（物理空间）
- S = Social（社会空间）
- D = Decision（决策空间）

**考法**：某具体场景应用属于哪个空间。
例：咖啡店收集消费数据分析并自动推送优惠 → **决策空间（D）**

### 数字化转型
- **数字化转型的核心**：不只是技术，而是商业模式的变革
- **三阶段**：数字化（digitization）→ 数据化（digitalization）→ 数字化转型（digital transformation）

### 项目集管理 vs 项目组合管理
| | 项目集（Program）| 项目组合（Portfolio）|
|--|----------------|---------------------|
| 目的 | 协同管理相关项目，获取单个项目无法实现的收益 | 战略对齐，最大化整体价值 |
| 关注 | 项目间依赖关系 | 资源分配，优先级排序 |

## PART H：案例分析必背框架

### 进度问题分析框架
**问题描述**：项目进度落后，关键路径活动延期
**原因分析**：
1. 进度计划不合理（未使用CPM/PERT识别关键路径）
2. 资源冲突（多项目共享资源未做平衡）
3. 需求变更频繁，范围蔓延
4. 风险识别不足，未设进度缓冲

**改进措施**：
1. 制定基于关键路径的进度计划，识别关键活动
2. 对关键活动进行资源优先保障
3. 建立变更控制机制，防止范围蔓延
4. 使用挣值分析（SPI）实时监控进度偏差
5. 必要时采用赶工或快速跟进

---

### 成本超支分析框架
**问题**：项目成本超支（AC > EV，CPI < 1）
**原因**：
1. 成本估算不准确（未采用自下而上估算）
2. 变更未及时更新预算
3. 资源费率变化未及时更新
4. 返工造成额外成本

**改进措施**：
1. 建立挣值管理系统，实时计算CPI/EAC
2. 严格变更控制，变更必须同步更新成本基准
3. 设置应急储备应对已知风险
4. 定期审查成本绩效，偏差超阈值立即采取纠正措施
