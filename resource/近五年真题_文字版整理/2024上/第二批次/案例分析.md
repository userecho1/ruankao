## 案例一：数字化转型项目（项目章程 + 敏捷管理）

### 问题1（10分）：项目章程的内容和作用

<details>
<summary>查看参考答案</summary>

**项目章程应包含的主要内容：**

1. **项目目的或批准项目的原因**：项目立项的业务依据。
2. **可测量的项目目标和成功标准**：具体、可量化的交付目标。
3. **高层级的项目描述、边界定义**：项目范围的初步界定。
4. **高层级的风险**：已知的主要风险。
5. **里程碑计划**：主要阶段和关键节点。
6. **批准的财务资源**：初步预算。
7. **关键干系人名单**：识别的主要干系人。
8. **项目审批要求**：谁批准什么以及由谁来签署项目章程。
9. **委派的项目经理及其权限**：项目经理的职责和授权范围。
10. **发起人或其他批准项目章程的人员的姓名和职权**：正式授权信息。

**项目章程的作用：**

1. 正式授权项目经理使用组织资源，开展项目工作。
2. 确立项目与组织战略之间的直接联系。
3. 为项目提供高层级的方向，是项目规划的起点。
4. 形成项目的正式认可，是项目立项的重要依据。

</details>

---

### 问题2（8分）：敏捷开发适用场景和实践方法

<details>
<summary>查看参考答案</summary>

**敏捷方法适用的项目特征：**

1. 需求不确定、易变化，需要快速响应市场变化。
2. 创新性强，产品形态需要在迭代中逐步明确。
3. 业务和技术专家能紧密协作，频繁互动。
4. 可交付小批量、可独立部署的功能增量。
5. 客户能够持续参与并及时提供反馈。

**常见敏捷实践：**

| 实践 | 描述 |
|-----|------|
| **Sprint/迭代** | 固定时间盒（1-4周），产出可演示的软件增量 |
| **每日站会** | 15分钟内同步昨日进展、今日计划和当前阻碍 |
| **迭代规划会** | Sprint开始前选择和分解待办事项 |
| **迭代回顾会** | Sprint结束后总结经验，持续改进流程 |
| **产品待办列表** | 按优先级排列的需求列表，动态维护 |
| **看板（Kanban）** | 可视化工作流，限制在制品数量 |
| **持续集成** | 频繁合并代码，自动构建和测试 |
| **结对编程** | 两名开发人员共用一台计算机协作编码 |

</details>

### 问题3（7分）：干系人管理

<details>
<summary>查看参考答案</summary>

**干系人管理的过程：**

| 过程 | 主要内容 |
|-----|--------|
| **识别干系人** | 识别所有可能影响项目或被项目影响的个人或组织 |
| **规划干系人参与** | 制定干系人参与管理计划，确定沟通策略 |
| **管理干系人参与** | 与干系人沟通协作，满足其需求，处理问题 |
| **监督干系人参与** | 监控干系人参与情况，调整策略 |

**干系人参与级别（5级）：**
- 不知晓 → 抵制 → 中立 → 支持 → 主导

**项目经理管理干系人的策略：**

1. 对"支持型"干系人：保持参与，及时沟通项目进展。
2. 对"中立型"干系人：提供信息，争取其支持。
3. 对"抵制型"干系人：深入了解其关切，沟通化解，或通过上级干预。
4. 对高权力/高兴趣干系人：重点管理，频繁双向沟通。
5. 对低权力/低兴趣干系人：监控即可，无需过多投入。

</details>

## 案例二：智慧交通项目（可行性研究 + 范围管理）

### 问题1（8分）：可行性研究报告的内容

<details>
<summary>查看参考答案</summary>

**可行性研究报告包括以下主要内容：**

1. **概述**：项目背景、建设目标、研究范围和结论。
2. **现状与差距分析**：现有系统状况和存在的问题。
3. **需求分析**：业务需求、功能需求、性能需求。
4. **技术可行性分析**：技术方案比较，技术成熟度，实现难点。
5. **经济可行性分析**：投资估算（建设成本+运维成本）、效益分析（财务效益+社会效益）、投资回收期。
6. **社会可行性分析**：政策符合性、社会影响评价。
7. **法律可行性分析**：是否符合相关法规、标准。
8. **风险分析**：主要风险识别和应对措施。
9. **建设方案**：推荐方案说明。
10. **结论与建议**：综合评价和决策建议。

</details>

---

### 问题2（10分）：WBS分解和范围说明书

<details>
<summary>查看参考答案</summary>

**WBS（工作分解结构）分解原则：**

1. **100%规则**：WBS必须涵盖项目范围的100%，不多不少。
2. **相互独立**：同一层级的工作包之间应相互独立、不重叠。
3. **可管理性**：最低层级的工作包应可估算、可分配、可监控。
8/80规则：工作包工期一般在8小时到80小时之间（2天以内可在两个汇报周期内完成）。
4. **面向可交付成果**：WBS关注成果（做什么），而非过程（怎么做）。

**项目范围说明书的主要内容：**

1. **产品范围描述**：详细描述项目可交付成果的特征和功能。
2. **可交付成果**：项目完成时产生的成果清单，包括中间成果。
3. **验收标准**：可交付成果验收的条件和方法。
4. **项目排除项**：明确哪些内容不在项目范围内（防止范围蔓延）。
5. **制约因素**：影响项目执行的条件（预算上限、监管要求等）。
6. **假设条件**：项目计划所基于的假设。

</details>

### 问题3（7分）：需求管理

<details>
<summary>查看参考答案</summary>

**需求的分类：**

| 类型 | 描述 |
|-----|------|
| **业务需求** | 组织实施项目的高层级目标（如提升交通效率20%） |
| **干系人需求** | 干系人对项目结果的期望（如司机需要实时路况提示） |
| **解决方案需求** | 满足业务和干系人需求的产品功能（功能需求+非功能需求） |
| **过渡需求** | 从当前状态迁移到未来状态的临时性需求（如数据迁移） |
| **项目需求** | 项目本身的管理需求（如进度报告频率、质量标准） |
| **质量需求** | 确认项目可交付成果符合质量标准的条件 |

**需求跟踪矩阵（RTM）的作用：**

1. 追踪需求从业务目标到可交付成果的链条，确保无遗漏。
2. 支持变更影响分析，评估需求变更对其他需求和交付物的影响。
3. 确保测试用例覆盖所有需求，保证验收完整性。

</details>

### 问题1（8分）：第7月末EVM计算

<details>
<summary>查看参考答案</summary>

**已知：截至第7月末完成了项目70%的工作量**

$$EV = 70\% \times BAC = 70\% \times 210 = \mathbf{147 \text{ 万元}}$$

$$PV = 150 \text{ 万元（第7月末累计计划价值）}$$

$$AC = 145 \text{ 万元（第7月末累计实际成本）}$$

**偏差计算：**

$$SV = EV - PV = 147 - 150 = \mathbf{-3 \text{ 万元（略落后进度）}}$$
$$CV = EV - AC = 147 - 145 = \mathbf{+2 \text{ 万元（成本略节省）}}$$

**绩效指数：**

$$SPI = \frac{EV}{PV} = \frac{147}{150} = \mathbf{0.98} \quad (\text{略落后，接近1})$$
$$CPI = \frac{EV}{AC} = \frac{147}{145} \approx \mathbf{1.014} \quad (\text{成本略优})$$

</details>

---

### 问题2（7分）：完工预测

<details>
<summary>查看参考答案</summary>

**方法一：典型偏差（CPI保持不变）**

$$ETC = \frac{BAC - EV}{CPI} = \frac{210 - 147}{1.014} = \frac{63}{1.014} \approx \mathbf{62.1 \text{ 万元}}$$

$$EAC = AC + ETC = 145 + 62.1 = \mathbf{207.1 \text{ 万元}} < BAC(210万)$$

$$VAC = BAC - EAC = 210 - 207.1 = \mathbf{+2.9 \text{ 万元（预计节省）}}$$

**方法二：剩余工作按计划完成**

$$ETC = BAC - EV = 210 - 147 = 63 \text{ 万元}$$
$$EAC = AC + ETC = 145 + 63 = \mathbf{208 \text{ 万元}}$$

</details>

---

### 问题3（10分）：进度预测和建议

<details>
<summary>查看参考答案</summary>

**进度预测（能否按期完工）：**

- 剩余工作量：$(1 - 70\%) \times 210 = 63$ 万元价值的工作
- 剩余计划时间：10 - 7 = 3个月
- 剩余计划每月工作量：20万元/月
- 按当前SPI推算：剩余63万元工作，若每月完成 $20 \times SPI = 20 \times 0.98 = 19.6$ 万元，则需要 $63 / 19.6 \approx 3.2$ 个月
- **预计超期约0.2个月（约6天）**

**结论：** 项目进度略微落后，按当前趋势预计略有超期，但偏差较小（SPI=0.98，偏差2%），在可接受范围内。

**建议措施：**

1. **局部赶工**：对剩余3个月的关键活动适当增加资源，弥补约2%的进度缺口。
2. **进度基准复核**：检查第7月进度放缓的原因（当月AC仅5万，异常偏低），排除数据录入错误。
3. **加强监控频率**：缩短进度汇报周期，每周监控关键里程碑达成情况。
4. **风险预案**：提前识别后续3个月的潜在风险（如节假日、人员变动），制定应急预案。
5. **成本保持**：CPI=1.014表明成本控制良好，继续保持当前成本控制措施。

</details>

### 附：挣值管理公式速查

| 公式 | 名称 | 解读 |
|-----|------|------|
| $EV = \%\text{完成} \times BAC$ | 挣值 | 已完成工作的计划价值 |
| $SV = EV - PV$ | 进度偏差 | >0超前，<0落后 |
| $CV = EV - AC$ | 成本偏差 | >0节省，<0超支 |
| $SPI = EV/PV$ | 进度绩效指数 | >1超前，<1落后 |
| $CPI = EV/AC$ | 成本绩效指数 | >1节省，<1超支 |
