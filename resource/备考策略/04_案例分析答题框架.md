# 案例分析答题框架与模板

> 评分逻辑：覆盖要点 > 分析深度。逐条列举，有编号，有结论，即可拿分。

---

## 通用答题原则

1. **逐条列举**，用1、2、3...编号
2. **每条：结论在前，依据在后**（一句话结论 + 一句话原因）
3. **不写废话**，直接给答案，不要长篇铺垫
4. 计算题：写公式 → 代入数据 → 给出结论句

---

## 时间分配建议

综合知识最多用150分钟，留至少90-100分钟给案例分析：
- 每道题：快速审题5min + 答题30min + 检查3min
- 先做把握高的，遇到不会的先跳过，最后回头填

## 高频题型模板

---

### 题型1：找问题/找错误

**答题格式：**
```
该项目存在以下问题：
1. [问题名称]：[具体描述，一句话说明违反了什么原则/缺少了什么]。
2. [问题名称]：[具体描述]。
3. ...
```

**常见问题角度（拿这些去套题目中的情况）：**
- 未制定/缺少XXX管理计划
- 变更未走变更控制流程（直接执行）
- 风险未及时识别/应对措施不当
- 缺乏与相关方的有效沟通
- 范围蔓延（未经批准的功能添加）
- 测试不充分（跳过测试阶段直接上线）
- 资源冲突未解决（关键人员过度分配）
- 缺乏配置管理（版本混乱）
- 进度基准未建立/未更新
- 项目章程未获批准就启动项目

---

### 题型2：提出改进措施/如何处理

**答题格式：**
```
针对上述问题，建议采取以下措施：
1. 应[做什么]，以[达到什么目的/避免什么风险]。
2. 应[做什么]，以[达到什么目的]。
3. ...
```

**配套措施方向：**
- 建立/完善XXX管理计划
- 按变更控制流程处理变更，报CCB审批
- 加强风险识别频次，更新风险登记册
- 增加与关键相关方的沟通频率
- 召开范围确认会，冻结需求基准
- 增加测试资源，严格执行测试计划
- 引入AB角制度，避免单点依赖

---

### 题型3：变更管理流程（几乎每年必考）

**标准答案（背熟）：**
```
正确的变更控制流程应为：
1. 提交变更申请：提出变更申请单，说明变更原因、内容及初步影响。
2. 影响评估：项目经理组织相关人员评估变更对范围、进度、成本、质量的影响。
3. CCB审批：将评估结果提交变更控制委员会（CCB）审议批准。
4. 执行批准的变更：按CCB批准的方案实施变更，更新项目管理计划和基准文件。
5. 拒绝则通知申请人：说明拒绝原因。
6. 跟踪变更执行：监控变更实施情况，确保变更按批准方案执行。
7. 记录变更日志：将全过程记录在变更日志中存档。
```

**常见错误（题目中的陷阱）：**
- 项目经理直接批准变更（应该CCB审批）
- 先执行变更再走流程（应先审批再执行）
- 不评估影响直接提交审批

### 题型4：挣值计算

详见《挣值计算公式》文件，按模板逐步计算即可。

**关键**：先写公式，再代数据，最后给文字结论。不写公式直接写结果会扣分。

### 题型5：风险管理题

**问"识别了哪些风险"时：**
```
根据题目描述，该项目存在以下风险：
1. [风险类型]：[描述]，可能导致[后果]。
2. ...
```

**问"应采取什么应对措施"时：**
```
针对上述风险，建议采取以下应对措施：
1. 对于[风险X]，采用[回避/转移/减轻/接受]策略：[具体措施]。
2. ...
```

**四种威胁应对策略含义（必背）：**
- **回避**：修改计划，使风险不再存在（成本高，用于高危风险）
- **转移**：购买保险、外包等，将风险后果转移给第三方
- **减轻**：降低风险发生概率或降低影响程度
- **接受（主动）**：制定应急计划，一旦触发立即执行
- **接受（被动）**：不做任何处理，等风险发生再说（低概率低影响时用）

### 题型6：沟通渠道计算

**公式：沟通渠道数 = n(n-1)/2**

**例题：** 项目团队由5人扩展到9人，新增沟通渠道数是多少？
```
原来：5×(5-1)/2 = 10条
现在：9×(9-1)/2 = 36条
新增：36 - 10 = 26条
```

### 题型7：关键路径计算

**步骤：**
1. 列出所有从开始到结束的路径
2. 计算每条路径的总时长
3. 最长路径 = 关键路径，关键活动总浮动时间 = 0
4. 总浮动时间 = 最晚完成时间 - 最早完成时间

**答题格式：**
```
（1）各路径时长：
路径A（活动1→2→4）：X+Y+Z = N天
路径B（活动1→3→4）：...

（2）关键路径为：路径X（时长N天），包含活动：...

（3）活动XX的总浮动时间 = N天（计算过程...）
```

### 题型8：配置管理

**配置管理流程（答题要点）：**
1. 配置识别：确定配置项，建立配置基线
2. 配置控制：对配置项的变更实施变更控制
3. 配置状态报告：记录和报告配置项的状态
4. 配置审计：验证配置项是否符合要求

**关键概念：**
- **配置基线**：经正式批准的一组配置项，只能通过变更控制流程修改
- **配置项**：纳入配置管理的硬件、软件、文档等
- 常见题目陷阱：开发人员私自修改已基线化的代码（违反配置管理原则）

---

### 题型9：合同类型选择

**题目通常问：在XXX情况下应选择哪种合同类型？**

选择逻辑：
- 需求明确，规模确定 → **固定总价（FFP）**（买方风险低）
- 需求不明确，规模难估 → **成本加XXX**（买方承担风险）
- 临时性、小批量工作 → **时间与材料（T&M）**
- 希望激励承包商降低成本 → **总价激励费用（FPIF）** 或 **成本加激励费用（CPIF）**

## 综合类"分析题"万能框架

当题目问"作为项目经理，你应该怎么做？"时：

```
作为项目经理，应采取以下步骤处理该问题：
1. 立即[紧急措施，控制当前损害]。
2. [评估影响]：评估此问题对项目范围、进度、成本、质量的具体影响。
3. [上报/沟通]：及时向项目发起人/客户/相关方通报情况。
4. [制定方案]：组织团队制定解决方案，提交CCB审批（如涉及变更）。
5. [更新计划]：更新项目管理计划相关文件，调整基准（如需要）。
6. [预防复发]：分析根本原因，采取预防措施，更新风险登记册和经验教训。
```
