论文二：成本管理（2026年次高概率命题）

⭐⭐ 必背！含EVM挣值管理计算，是论文里最有"干货"的一篇。
2022年考过，距今已过4年，2026年再考概率高。

摘要（约300字）

本文以XX集团数字化业务中台建设项目为例，结合本人担任项目经理的实践经验，论述了成本管理在敏捷信息化项目中的全过程应用。该项目由XX制造集团发起，旨在整合集团内部分散的ERP、CRM、WMS、OA等多个异构系统，构建统一的数字化业务中台。项目总预算680万元，建设周期14个月，项目团队共16人，采用Scrum敏捷开发框架。

在项目实施过程中，本人面临遗留系统集成复杂度难以准确估算、敏捷环境下成本基准易受需求变更侵蚀、多Release并行推进导致成本波动较大等挑战。为此，本人采取了基于故事点（Story Point）的敏捷估算法结合自下而上估算校验、将挣值管理（EVM）与敏捷速度指标相融合进行成本监控、以及严格的变更成本评估等措施。通过科学的成本管理，项目最终在预算范围内顺利完成，实际成本较预算节约约2.8%，甲方满意度评分4.8分（满分5分）。

本文将从成本管理计划制定、成本估算方法、挣值分析应用、成本控制措施等方面进行系统总结。

正文

一、项目概述

2023年4月，本人受命担任XX集团数字化业务中台建设项目的项目经理。该项目旨在整合集团内部分散的ERP、CRM、WMS、OA等系统，构建统一的数字化业务中台。项目总预算680万元，建设周期14个月，团队由16名成员组成，采用Scrum敏捷框架，以2周为一个Sprint迭代交付。

本项目成本管理面临以下主要挑战：一是遗留系统数据接口文档不完整，技术复杂度难以在项目初期准确估算，成本存在较大不确定性；二是敏捷环境下业务需求允许在Sprint间调整，若成本管控不到位，极易导致范围蔓延引发超支；三是团队成员来自不同技术背景，人力成本结构复杂，需要精细化的成本追踪机制。

二、成本管理的实施过程

（一）制定成本管理计划

在项目规划阶段，本人制定了成本管理计划，明确以下核心内容：成本估算采用故事点敏捷估算结合自下而上估算双轨校验；成本绩效基准以Release为单位制定，三个Release预算分别为220万元、230万元、180万元，管理储备30万元；成本绩效监控采用挣值管理（EVM），预警阈值设定为CPI<0.9时启动成本预警；成本变更控制规定单笔超出Sprint预算10%以上的资源调整须提交CCB审批；成本报告频率为每月一次，通过项目状态报告向指导委员会汇报。

（二）成本估算

本项目采用"故事点估算+自下而上估算"双轨估算方法：

故事点估算（敏捷层面）：在产品Backlog梳理会上，团队使用规划扑克（Planning Poker）对用户故事进行故事点估算。结合历史项目数据，初步确定团队速度（Velocity）约为每Sprint完成40个故事点，全项目估算总量约1100个故事点，对应约28个Sprint。

自下而上估算（成本精算）：将故事点映射为对应工时，结合各岗位日费率，计算出人力成本约占总预算65%，约为442万元。其余包括云服务器及基础设施租用费约占10%（68万元）、软件授权费约占8%（54万元）、外包测试与安全评估约占7%（48万元）、应急储备约占5%（34万元）、管理储备约占4.4%（30万元）。

估算完成后，本人邀请1位曾主导类似中台建设项目的公司技术总监进行同行评审，对工时估算偏低的关键模块进行了上调修正，提升了估算可信度。

（三）制定成本基准

将经批准的成本估算按三个Release进行时间段分配，形成成本绩效基准（S曲线）。S曲线展示了14个月内各时间点的累计计划支出，作为后续挣值分析的参照基准。成本绩效基准经项目指导委员会批准后正式生效。

（四）成本控制与挣值管理应用

项目执行阶段，本人每月收集一次实际成本数据，运用挣值管理进行绩效分析。在敏捷项目中，"已完成工作的预算价值（EV）"以当前Sprint为止已验收的故事点所对应的计划成本来计算。

第9个月挣值分析：

计划价值 PV = 440万元（对应第9个月应完成工作的预算价值）；
已完成故事点对应挣值 EV = 410万元；
实际成本 AC = 455万元。

成本偏差 CV = EV - AC = 410 - 455 = -45万元（成本超支）；
成本绩效指数 CPI = EV / AC = 410 / 455 ≈ 0.902，低于预警阈值0.9边界，触发成本预警。

进度偏差 SV = EV - PV = 410 - 440 = -30万元（进度略有滞后）；
进度绩效指数 SPI = EV / PV = 410 / 440 ≈ 0.932。

完工估算 EAC = BAC / CPI = 680 / 0.902 ≈ 754万元（超出预算约74万元），存在超支风险。

深入分析发现，成本超支主要来自两方面：其一，ERP接口对接技术难度远超预估，额外投入约30个工日；其二，因甲方业务需求变更导致已开发功能模块两次返工，产生额外成本约20万元。

针对上述情况，本人采取了以下成本控制措施：

第一，优化技术方案。与架构师重新审视ERP接口对接方案，将原本计划自研的适配层改为采用成熟的中间件产品（已有商业授权），将技术实现工作量从约40工日压缩至18工日，节约人力成本约13万元。

第二，强化变更成本评估。在后续的变更申请中，强制要求提交方同步提供成本影响估算，CCB审议时将成本影响纳入决策因素，将与核心目标关联度低的3项功能变更延至二期，规避了约25万元的潜在超支。

第三，优化团队资源配置。对任务负荷分析后，将2名在当前Sprint任务较少的前端工程师临时调配支援测试工作，减少了外包测试的费用支出，节约约8万元。

第四，动用部分应急储备。经CCB审批，动用应急储备24万元，解决了ERP接口对接超支问题，未动用管理储备。

通过上述措施，项目后续阶段CPI逐步回升至1.05以上，成功扭转了超支趋势。

三、项目成果与体会

项目最终于2024年5月按期完成交付，实际总成本约661万元，较批准预算680万元节约约19万元（节约率约2.8%），成本绩效良好。系统上线后首月故障率低于0.1%，甲方满意度评分4.8分（满分5分）。

通过本项目的实践，本人深刻认识到：在敏捷项目中，成本管理不能因为"需求允许灵活变化"就放弃成本基准的约束。挣值管理在敏捷环境中同样适用，只需将"已验收的故事点价值"作为EV的计量标准即可。成本管理与变更控制必须紧密配合——每一个未经成本评估的需求变更，都是潜在的超支隐患。精细化的成本追踪和数据驱动的预警机制，是项目经理主动管理而非被动应对成本问题的关键。

在今后的项目管理实践中，本人将持续深化成本管理能力，在敏捷与规范化成本控制之间找到最优平衡，为组织持续交付高价值、高性价比的项目成果。
