案例一：软件项目管理（整合管理 + 变更管理）

问题1（10分）：项目管理方面存在的问题

查看参考答案
  1. 范围蔓延：合同签订后不断增加新功能（如新增对公缴费、数据追溯等），但未通过正式变更控制流程处理，导致范围无限扩大。
  2. 变更管理失控：未建立变更控制委员会（CCB），无正式的变更申请、评估和批准流程，客户直接向开发人员提需求，绕过项目管理层。
  3. 进度管理失当：由于需求频繁变更，进度计划不断被打乱，但项目经理未采取有效的进度基准维护和纠偏措施。
  4. 缺乏基准管理：范围基准、进度基准和成本基准随变更无序调整，失去了控制项目的基准参考。
  5. 干系人管理不足：用户单位负责人直接与开发人员沟通需求，信息未汇聚到项目经理处，干系人管理缺失。
  6. 合同管理薄弱：新增工作超出合同范围，未及时签订补充协议，导致成本超支无法追回。
  7. 风险管理缺失：缺少对新需求带来的进度风险、成本风险的识别和应对。

问题2（8分）：变更管理流程

查看参考答案

完整的变更控制流程（8步）：

  1. 提交变更申请：变更申请人填写变更请求单，描述变更内容、变更原因和影响范围。
  2. 记录变更请求：将变更请求纳入变更日志，统一编号管理。
  3. 变更评估分析：项目经理组织对变更影响进行评估（范围、进度、成本、质量、风险等方面）。
  4. CCB审批：变更控制委员会评审变更请求，决定批准、拒绝或延期。
  5. 制定变更实施方案：对批准的变更制定详细实施计划，分配资源。
  6. 执行变更：按变更实施方案落实变更内容，更新相关文件。
  7. 验证变更：确认变更已按要求正确实施，验收变更结果。
  8. 关闭变更请求：更新变更日志，将变更结果归档，更新项目基准。

问题3（7分）：集成变更控制的主要作用

查看参考答案

集成变更控制的主要作用：

  1. 维护配置基准：确保项目范围、进度、成本、质量基准在受控状态下变更，不被随意修改。
  2. 综合评估变更影响：变更往往影响多个知识领域，集成变更控制确保对所有影响的全面评估。
  3. 避免范围蔓延：通过正式流程控制范围变更，防止未授权的范围扩大。
  4. 确保信息透明：所有变更均有记录，项目状态对干系人保持透明。
  5. 协调配置管理：与配置管理系统协调，确保产品与项目文件的版本一致性。
  6. 支持决策：为CCB提供全面的变更影响分析，支持科学决策。

案例二：智慧园区项目（采购管理 + 合同管理）

问题1（10分）：采购文件准备和供应商选择的问题

查看参考答案

存在的问题：

  1. 采购文件内容不完整：工作说明书（SOW）描述不够详细，仅描述了总体功能，未细化各模块的技术要求、接口要求、性能指标。
  2. 评标标准不透明：未在采购文件中明确评标方法和权重，导致选供应商带有主观随意性。
  3. 未进行市场调研：直接编制采购文件，未充分了解市场上供应商的能力状况，采购预算缺乏依据。
  4. 供应商选择标准过于注重价格：应综合考虑供应商的技术能力、案例、财务状况、售后服务能力等因素。
  5. 未要求供应商做方案答辩：对于复杂项目，仅凭书面投标文件难以判断供应商真实能力。
  6. 合同风险分配不合理：合同中关于延期违约责任和技术规格偏差责任的约定不明确，导致后期纠纷。

问题2（6分）：合同管理存在的问题及建议

查看参考答案

问题：

  1. 合同变更未书面化：项目实施过程中增加功能，双方通过口头协议或会议纪要处理，未签订正式补充合同。
  2. 合同条款不完善：原合同未包含知识产权归属、数据安全保密条款，后续引发争议。
  3. 缺乏合同绩效考核机制：未在合同中规定定期绩效检查节点，导致问题积累到验收才发现。
  4. 供应商管理缺位：项目团队对供应商日常工作缺少跟踪，进展不透明。

建议：

  1. 所有变更均应签订书面补充协议，明确变更内容、工期和费用调整。
  2. 在原合同中完善知识产权、保密、数据安全等条款。
  3. 建立里程碑检查机制，定期评估供应商绩效。
  4. 指定专人负责合同管理，建立合同台账。

（2）活动D的总时差：

  • 从关键路径角度：LF(H) = 98-30 = 68（J的ES = 68）

问题3（7分）：偏差分析和PERT计算

查看参考答案

偏差计算：

$$SV = EV - PV = 70 - 80 = \mathbf{-10 \text{ 万元（落后进度）}}$$
$$CV = EV - AC = 70 - 70 = \mathbf{0 \text{ 万元（成本持平）}}$$
$$SPI = \frac{EV}{PV} = \frac{70}{80} = \mathbf{0.875}$$
$$CPI = \frac{EV}{AC} = \frac{70}{70} = \mathbf{1.0}$$

偏差判断：
- SPI = 0.875，偏差为 (1-0.875)/1 × 100% = 12.5%，超过10%的阈值，需采取纠正措施。
- CPI = 1.0，成本执行正常，无需干预。

纠正措施：
1. 加快D和E的进度（若尚未完工），增加资源。
2. 为后续关键活动F提前准备资源，减少启动延迟。
3. 重新评估关键路径，制定赶工计划。

F活动的PERT计算（三点估算）：

题目给出：乐观工期O=19天，悲观工期P=31天，最可能工期M=25天。

$$t_e = \frac{O + 4M + P}{6} = \frac{19 + 4 \times 25 + 31}{6} = \frac{19 + 100 + 31}{6} = \frac{150}{6} = \mathbf{25 \text{ 天}}$$

$$\sigma = \frac{P - O}{6} = \frac{31 - 19}{6} = \frac{12}{6} = \mathbf{2 \text{ 天}}$$

$$\sigma^2 = 4 \text{ 天}^2$$

F在27天内完成的概率：

$$Z = \frac{T - t_e}{\sigma} = \frac{27 - 25}{2} = 1.0$$

查标准正态分布表：$P(Z \leq 1.0) = \mathbf{84.13\%}$

结论：F活动在27天内完成的概率为84.13%。
