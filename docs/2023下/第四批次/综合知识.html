逐题解析

第1题 【信息技术应用】

题目： 微信中语音转换为文字的功能，主要应用了（ ）技术。

A、虚拟现实
B、专家系统
C、自然语言处理
D、大数据

查看答案与解析

答案：C — 自然语言处理（NLP）

解析： 语音转文字是自动语音识别（ASR）与自然语言处理（NLP）的典型应用场景。
- 虚拟现实（A）：沉浸式体验技术，与语音转文字无关。
- 专家系统（B）：基于规则的推理系统，不用于语音识别。
- 大数据（D）：数据处理与分析框架，不是语音转文字的核心技术。

第3题 【沟通管理】

题目： （ ）不属于书面沟通的5C原则。

A、简洁的表述（concise）
B、可以证明的结论（certification）
C、连贯的思维逻辑（coherent）
D、清晰的目的和表述（clarity）

查看答案与解析

答案：B — 可以证明的结论（certification）

解析： 书面沟通5C原则：
- Correct（正确的）
- Concise（简洁的）——对应选项 A
- Clear（清晰的）——对应选项 D
- Coherent（连贯的）——对应选项 C
- Controlling（可以控制的，有效控制信息流）

"certification（可以证明的结论）"并不是5C之一，故选 B。

第5题 【IT服务管理】

题目： GB/T 28827.1《信息技术服务 运行维护 第1部分：通用要求》定义的IT运维能力模型包含治理要求、运行维护服务能力体系和价值实现，其中（ ）为价值实现赋能。

A、用户需求
B、治理要求
C、战略要求
D、运维服务能力体系

查看答案与解析

答案：D — 运维服务能力体系

解析： IT运维能力模型三大组成部分：治理要求（约束框架）、运行维护服务能力体系（赋能主体）、价值实现（目标）。其中运维服务能力体系是为价值实现赋能的核心支撑，A、B、C均不符合题意。

第6题 【合同管理】

题目： （ ）是解决所有索赔和争议的首选方法。

A、申诉
B、谈判
C、起诉
D、替代争议解决方法（ADR）

查看答案与解析

答案：B — 谈判

解析： PMBOK明确指出，谈判（直接谈判）是解决采购合同索赔与争议的首选方法，因为成本最低、速度最快，且有利于维持双方合作关系。申诉（A）、起诉（C）成本高、周期长；ADR（D）是谈判失败后的备选手段。

第9题 【规划绩效域】

题目： 规划绩效域中，可以应用（ ）检查项目是否以有条理、协调一致的方式推进。

A、绩效偏差
B、规划的详尽程度
C、规划的充分性
D、规划的整体性

查看答案与解析

答案：D — 规划的整体性

解析： PMBOK第7版规划绩效域绩效要点：
- 规划的整体性：检查计划是否有条理、相互协调、一致推进——对应题意，选 D。
- 规划的充分性（C）：检查计划内容是否充分。
- 规划的详尽程度（B）：检查计划细化程度。
- 绩效偏差（A）：属于测量绩效域的概念。

第11题 【沟通管理】

题目： 项目经理需在项目生命周期的（ ），针对项目干系人多样性的信息需求，制订有效的沟通管理计划。应该在（ ）期间，定期审查本过程的成果并做必要修改，以确保其持续适用。

A、前期　项目后期
B、早期　整个项目
C、中期　项目后期
D、整个周期　项目中期

查看答案与解析

答案：B — 早期；整个项目

解析： 沟通管理计划应在项目早期制订（不是"前期"或"整个周期"），以便尽早识别干系人需求；并在整个项目期间持续审查更新，以适应不断变化的情况。选项 A、C、D 的时间搭配均不正确。

第12题 【项目管理原则】

题目： 某跨国企业需要建设覆盖多个国家的人力资源系统，项目经理在规划系统建设时对系统覆盖多个国家的文化规范、语言、时区等问题进行了充分的调研，确保了该系统满足管理需要，这是价值驱动的项目管理原则中（ ）原则的体现。

A、展现领导力行为
B、驾驭复杂性
C、为实现目标而驱动变革
D、促进干系人参与

查看答案与解析

答案：B — 驾驭复杂性

解析： "驾驭复杂性"原则要求识别并应对项目复杂性来源，包括：系统交互、不确定性、技术复杂度、法律、多元文化差异等。题目中多国文化规范、语言、时区正是复杂性的典型来源，充分调研正是驾驭复杂性的体现，故选 B。

第14题 【项目立项】

题目： 项目评估的依据主要包括：项目建议书及其批准文件、（ ）报送组织的申请报告及主管部门的初审意见、项目关键建设条件和工程等的协议文件、必需的其他文件和资料等。

A、需求调研报告
B、绩效测量报告
C、成本预测报告
D、项目可行性研究报告

查看答案与解析

答案：D — 项目可行性研究报告

解析： 项目评估是由专业机构对项目可行性研究结论进行审查的过程，其核心依据是项目可行性研究报告。评估在可行性研究完成后开展，以可行性研究报告为主要输入，A、B、C均不符合题意。

第17题 【干系人管理】

题目： （ ）is about stakeholders. It is based on three variables: power to influence, legitimacy of the stakeholders' relationships with the project, and the urgency of the stakeholders' claim on the project for stakeholder engagement.

A、The SPACE Matrix
B、The PEST Model
C、The SWOT Analysis
D、The Salience Model

查看答案与解析

答案：D — The Salience Model（显著性模型）

解析： 干系人显著性模型（Salience Model）正是基于三个维度对干系人进行分类分析：
- 权力（Power）：影响项目的能力
- 合法性（Legitimacy）：与项目关系的合理性
- 紧迫性（Urgency）：对项目诉求的迫切程度

SPACE Matrix（A）是战略规划工具；PEST Model（B）和SWOT Analysis（C）是环境分析工具，均与干系人分析无关。

第19题 【物联网架构】

题目： 车联网系统是一个"端、管、云"三层体系。其中（ ）解决互联互通问题，（ ）是多源海量信息的汇聚。

A、云系统　端系统
B、端系统　云系统
C、端系统　管系统
D、管系统　云系统

查看答案与解析

答案：D — 管系统；云系统

解析： 车联网"端、管、云"三层架构：
- 端系统（车载终端/感知层）：数据采集与感知。
- 管系统（通信网络层）：负责互联互通，是数据传输通道。
- 云系统（云平台/应用层）：多源海量信息的汇聚、存储与分析。

故第一空填"管系统"，第二空填"云系统"，选 D。

第20题 【软件部署】

题目： （ ）是指当有新版本发布的时候，先让少量用户使用新版本，并且观察新版本是否存在问题。如果出现问题，就及时处理并重新发布；如果一切正常，就稳步地将新版本适配给所有的用户。

A、蓝绿部署
B、金丝雀部署
C、虚拟机部署
D、持续部署

查看答案与解析

答案：B — 金丝雀部署

解析：
- 金丝雀部署（Canary Deployment）：先将新版本推送给小比例用户，验证无误后再逐步扩大，与题目描述完全吻合，选 B。
- 蓝绿部署（A）：维护两套环境（蓝/绿），一键切换，非渐进式。
- 虚拟机部署（C）：部署方式，与灰度发布无关。
- 持续部署（D）：自动化持续交付流程概念，非灰度发布策略。

第23题 【干系人管理】

题目： 适用于监督干系人参与过程的数据表现技术是（ ）。

A、沟通技能
B、根本原因分析
C、干系人参与度评估矩阵
D、干系人分析技术

查看答案与解析

答案：C — 干系人参与度评估矩阵

解析： 监督干系人参与过程的数据表现技术是干系人参与度评估矩阵，通过对比干系人当前参与水平（C）与期望参与水平（D），识别差距并制定调整策略。沟通技能（A）属于人际关系技能，根本原因分析（B）属于数据分析技术，干系人分析技术（D）属于识别干系人过程的技术。

第25题 【项目管理信息系统】

题目： 项目管理信息系统包括（ ）软件，用于监督资源的使用情况，协助确保合适的资源适时、适地用于合适的活动。

A、资源管理或进度计划
B、CRM系统
C、采购系统或智能分析
D、BOM系统

查看答案与解析

答案：A — 资源管理或进度计划

解析： PMIS（项目管理信息系统）中，资源管理软件或进度计划软件（如 MS Project、Primavera 等）直接用于监督资源使用、进度安排，确保资源按需分配。CRM（B）是客户关系管理；BOM（D）是物料清单；采购系统（C）不直接服务于资源监控。

第26题 【配置管理】

题目： 功能配置审计内容包含：（ ）。

①交付配置项是否存在
②配置项已达到配置标识中规定的性能和功能特征
③配置项中是否包含了所有必须的项目
④配置项的开发已圆满完成
⑤配置项的操作和支持文档已完成并且是符合要求的

A、②④⑤
B、①③④
C、①②④⑤
D、②③④

查看答案与解析

答案：A — ②④⑤

解析： 配置审计分两类：
- 功能配置审计（FCA）：审核功能/性能特征是否达到（②）、开发是否完成（④）、操作与支持文档是否完整（⑤）。
- 物理配置审计（PCA）：审核配置项实体是否存在（①）、是否包含全部必须项（③）。

故功能配置审计内容为②④⑤，选 A。

第27题 【成本估算】

题目： （ ）估算方法将以往类似项目的相关信息作为估算未来项目的基础，是一种快速估算方法，适用于项目经理只能识别WBS的几个高层级的情况。

A、类比
B、基线
C、自下而上
D、参数

查看答案与解析

答案：A — 类比估算

解析： 类比估算（Analogous Estimation）利用历史类似项目的参数估算当前项目，适用于信息不充分的早期阶段，是"快速但粗略"的方法，且只需识别WBS高层级即可使用。
- 参数估算（D）需要建立统计关系模型。
- 自下而上估算（C）需要详细完整的WBS。
- 基线（B）是控制参照基准，不是估算方法。

第29题 【质量成本】

题目： 与项目有关的质量成本（COQ）包含以下一种或多种成本：（ ）、评估成本、失败成本（内部/外部）。

A、纠错成本
B、开发成本
C、测试成本
D、预防成本

查看答案与解析

答案：D — 预防成本

解析： 质量成本（COQ）完整框架共四类：
- 预防成本：防止缺陷发生（培训、流程改进、质量规划）
- 评估成本：评估可交付成果（测试、检查、审核）
- 内部失败成本：交付前发现缺陷（返工、废料）
- 外部失败成本：交付后发现缺陷（保修、退货、赔偿）

题目中已列出"评估成本"和"失败成本"，空白处填预防成本，选 D。

第32题 【投资决策】

题目： 甲公司对某投资项目进行评估，投入100万元，10%概率获得利润150万元，55%概率获得利润200万元，20%概率获得利润280万元，10%概率不赔不赚，5%概率亏300万元。则项目的投资回报率为（ ）。

A、266
B、2.66
C、166
D、1.66

查看答案与解析

答案：C — 166

解析： 计算期望利润（加权平均）：

$$E = 150×10\% + 200×55\% + 280×20\% + 0×10\% + (-300)×5\%$$
$$= 15 + 110 + 56 + 0 - 15 = 166 \text{（万元）}$$

$$投资回报率 = \frac{期望利润}{投入成本} × 100\% = \frac{166}{100} × 100\% = 166\%$$

故选 C（166%）。

第35题 【风险管理】

题目： 整体项目风险应对策略不包括（ ）。

A、开拓
B、接受
C、上报
D、转移或分享

查看答案与解析

答案：C — 上报

解析： 整体项目风险的应对策略（五种）：
- 规避（Avoid）/ 开拓（Exploit）：针对威胁/机会的极端应对
- 转移（Transfer）/ 分享（Share）：将风险转给第三方
- 减轻（Mitigate）/ 加强（Enhance）：降低/提高概率或影响
- 接受（Accept）：主动或被动接受风险

上报（Escalate）是单个项目风险超出项目经理权限时使用的策略，属于单个风险应对策略，而非整体项目风险应对策略，故选 C。

第36题 【干系人识别】

题目： 识别项目干系人管理过程在（ ）可以重复开展。

①每个阶段开始时
②项目出现重大变化时
③进行可行性研究时
④组织出现重大变化时
⑤编制项目章程时

A、③④⑤
B、①②③
C、②③④
D、①②④

查看答案与解析

答案：D — ①②④

解析： 识别干系人过程可重复开展的三个时机：
- 每个项目阶段开始时①：进入新阶段可能出现新干系人。
- 项目出现重大变化时②：变化可能引入新利益相关方。
- 组织出现重大变化时④：组织重组导致干系人结构变化。

③进行可行性研究 和 ⑤编制项目章程 属于项目初始识别，不是"重复开展"场景，故排除，选 D。

第39题 【决策分析】

题目： 某企业新研发的产品要投入市场，有三种价格方案ABC，预估每种价格方案的三种销售状态，根据同类产品的销售经验，算出三种价格方案下三种销售状态的收益值如表所示，该企业根据后悔值决策标准，应选择（ ）方案。

价格方案 销路较好 销路一般 销路较差
A方案 34 25 22
B方案 30 30 24
C方案 26 28 26

A、B方案
B、B方案或C方案
C、C方案
D、A方案

查看答案与解析

答案：A — B方案

解析： 后悔值决策标准（Minimax Regret）步骤：

第一步： 找每列（每种销售状态）最大收益值：
- 销路较好：max = 34（A方案）
- 销路一般：max = 30（B方案）
- 销路较差：max = 26（C方案）

第二步： 计算各方案在各状态下的后悔值（= 该列最大值 − 该方案收益）：

价格方案 销路较好后悔值 销路一般后悔值 销路较差后悔值 最大后悔值
A方案 34-34 = 0 30-25 = 5 26-22 = 4 5
B方案 34-30 = 4 30-30 = 0 26-24 = 2 4 ✓
C方案 34-26 = 8 30-28 = 2 26-26 = 0 8

第三步： 选最大后悔值最小的方案：B方案（最大后悔值=4）最小，选 A（B方案）。

第40题 【项目章程】

题目： 项目章程可由发起人编制，也可由项目经理与（ ）合作编制。通过这种合作，项目经理可以更好地了解项目的目的、目标和预期收益，以便更有效地分配项目资源。

A、发起机构
B、评估机构
C、客户
D、干系人

查看答案与解析

答案：A — 发起机构

解析： 《PMBOK》明确：项目章程可由发起人编制，或由项目经理与发起机构（sponsoring organization）合作编制。合作的目的是让项目经理更深入了解项目目的与预期收益，从而更有效分配资源。评估机构（B）、客户（C）、干系人（D）不参与章程编制。

第42题 【工作分解结构】

题目： （ ）is the hierarchical breakdown of the entire scope of work by the project team to accomplish the project objectives and create the required deliverables. It provides detailed deliverable, activity, and scheduling information about each component in the work breakdown structure.

A、OLA
B、SLA
C、SOP
D、WBS

查看答案与解析

答案：D — WBS（工作分解结构）

解析： 题目描述的是将项目全部工作按层级分解、提供可交付成果/活动/进度信息的结构，正是 WBS（Work Breakdown Structure，工作分解结构）的定义。
- OLA（A）：运营级别协议（Operational Level Agreement）
- SLA（B）：服务级别协议（Service Level Agreement）
- SOP（C）：标准操作程序（Standard Operating Procedure）

第49题 【项目定义】

第63题 【开发方法选择】

题目： 高风险的产品需要大量的前期规划和严格的流程来降低风险，可采用（ ）开发方法，新药开发项目可能会进行（ ），临床前建议、第1阶段临床试验结果、第2阶段临床试验结果、第3阶段临床试验结果、注册和上市，按照顺序进行交付。

A、混合型　多次交付
B、混合型　定期交付
C、预测型　多次交付
D、适应型　持续交付

查看答案与解析

答案：C — 预测型；多次交付

解析：
- 预测型（瀑布型）开发方法：适合高风险产品，需要大量前期规划和严格流程来降低风险，与题目描述吻合。
- 多次交付（multiple deliveries）：新药开发按临床前→Ⅰ期→Ⅱ期→Ⅲ期→注册上市顺序交付，属于多次交付（非定期交付，因为每阶段时间不固定）。

故选 C。

第64题 【项目文件】

题目： 由客户或者发起人正式签字批准的文件是（ ）。

A、核实的可交付成果
B、工作绩效信息
C、验收的可交付成果
D、可交付成果

查看答案与解析

答案：C — 验收的可交付成果

解析： 四个概念辨析：
- 可交付成果（D）：项目过程中产生的任何产品/服务/结果，尚未经过验收。
- 核实的可交付成果（A）：通过控制质量过程检验后确认符合质量要求的成果，但尚未由客户/发起人签署。
- 验收的可交付成果（C）：经客户或发起人正式签字批准的成果，是确认范围过程的输出，与题意完全匹配，选 C。
- 工作绩效信息（B）：绩效数据分析后的信息，与签字验收无关。
